A TailorKit app is a sandboxed extension built separately from the host product and served as a runtime bundle. It renders inside the host's UI using the host's own components, data, and actions — not custom HTML you control directly. The host decides how components look and behave; your app decides what to show and when.

## What you'll need

Before you start building, make sure you have the following in place:

- **Node.js 18 or later** installed on your machine
- **A running host app** that has TailorKit integrated and its handler available at `/api/tailorkit` (or a custom path you specify)
- **pnpm** (recommended) or npm/yarn for package management

<Note>
  You don't need access to the host's source code to build an app. TailorKit generates typed bindings from the host's published schema, so you can build against any host that exposes a TailorKit handler.
</Note>

## Project structure

When you scaffold a new TailorKit app with the CLI, it creates the following layout:

```txt
src/
  client.ts              # Registers the app's views per slot
  views/default.tsx      # Implements the default view
  tailorkit.gen.ts       # Generated host bindings — do not edit
tailorkit.config.ts      # Host URL, app ID, entry, and build options
package.json
```

**`src/client.ts`** — the entry point of your app. It calls `defineClient` to register which views your app provides for each host slot.

**`src/views/default.tsx`** — a starter view implementation. Add more files under `src/views/` as your app grows.

**`src/tailorkit.gen.ts`** — auto-generated by `pnpm generate`. Contains typed bindings for every component, action, view, and slot the host exposes. Never edit this file manually — regenerate it whenever the host schema changes.

**`tailorkit.config.ts`** — configuration for your app: the host URL to generate from and deploy to, your app's ID (written here after first deployment), and optional build overrides.

## The development loop

Building a TailorKit app follows a repeatable cycle from scaffold to live preview:

<Steps>
  <Step title="Scaffold the app">
    Use the CLI to create a new app project pointed at your host:

    ```sh
    pnpm dlx @tailorkit/cli init . \
      --name my-app \
      --host http://localhost:3000/api/tailorkit
    cd my-app
    ```
  </Step>

  <Step title="Generate host bindings">
    With the host running, pull its current schema into your project:

    ```sh
    pnpm generate
    ```

    This writes `src/tailorkit.gen.ts` with typed components, actions, and view contexts. Re-run this command whenever the host adds or changes views, components, actions, or theme tokens.
  </Step>

  <Step title="Implement your views">
    Edit `src/views/default.tsx` (or add new view files) to build your extension UI using components and context from `#tailorkit`.
  </Step>

  <Step title="Login and deploy">
    Authenticate the CLI with the host, then make your first deployment to create the app record:

    ```sh
    pnpm exec tailorkit login
    pnpm deploy
    ```

    The CLI writes your new `appId` to `tailorkit.config.ts` automatically.
  </Step>

  <Step title="Preview live">
    Start a live preview session that rebuilds and re-uploads on every save:

    ```sh
    pnpm exec tailorkit preview
    ```

    Open the printed link in your host, choose **Accept preview**, and your app appears in the host sandbox.
  </Step>

  <Step title="Deploy to production">
    When you're ready to ship, build and deploy the production bundle:

    ```sh
    pnpm build
    pnpm deploy
    ```
  </Step>
</Steps>
